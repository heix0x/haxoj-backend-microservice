# 功能解剖（anatomy）

> 极小颗粒度功能讲解：**一篇解剖一个类/机制**，同时回答两件事——
> 「它怎么工作」（代码层面的完整链路）与「为什么这么设计」（抽象思想层面）。
> 本目录随代码更新，不是历史存档。最后更新：2026-10-30

---

## 1. 目录命名建议

本目录在建名时的候选与取舍（留档，方便将来更名时对照）：

| 候选名 | 含义 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **`anatomy/`** | 功能解剖 | 隐喻统一：每篇是一个器官的解剖图；短、可检索；与"极小颗粒度"天然契合 | 中文读者需一秒反应 | **✅ 采用** |
| `mechanics/` | 机制讲解 | 语义准确 | 偏"物理机制"，与业务功能稍隔一层 | 备选一 |
| `micro-notes/` | 微笔记 | 直接对应"极小颗粒度" | 与 `notes/` 只差一个前缀，两目录极易混淆 | 否（混淆成本高） |
| `feature-notes/` | 功能笔记 | 直白 | 同上，与 `notes/` 边界不清 | 否 |
| `deep-dives/` | 深度长文 | 常见惯例 | 暗示"长而全"，与"小颗粒"相反 | 否 |
| `详解/` | 中文直译 | 零理解成本 | 与现有英文目录名（`adr/`、`notes/`）不一致 | 否 |

**选定理由**：`notes/` 已占用"笔记"心智（日期流水账），新目录必须在名字上就与它区分开。
"解剖"恰好定义了文体差异——不是记录经历，而是拆开细看。
当前目录内文件极少，若将来更名，成本只是改目录名 + 修几处相对链接。

## 2. 文档存放规范

### 2.1 放什么 / 不放什么

| 内容 | 归属 | 理由 |
|---|---|---|
| 单个类/接口/机制的端到端讲解（代码链路 + 设计思想） | **本目录** | 活文档，随代码更新 |
| 某次改造的背景、决策、踩坑、实测 | [`../notes/`](../notes/) | 实现记录，同一主题一份正文、就地更新 |
| 「当初为什么选 A 不选 B」的决策 | [`../adr/`](../adr/) | 一条一决策，结论变更就地更新 |
| 系统全景（模块、端口、数据流） | [`../architecture.md`](../architecture.md) | 一张地图 |
| 面试题式的八股复述、"代码要优雅"式空话 | 不写 | 本仓库文档规则：不写正确的废话 |

### 2.2 文件命名

| 解剖对象 | 文件名 | 例 |
|---|---|---|
| 单个类/接口 | 与其简单类名**完全一致**（方便 Ctrl+P 对上代码） | `JudgeMessageConsumer.md` |
| 跨类协作的机制 | 机制名（中文短语，10 字内） | `判题状态机.md`、`原子抢占与幂等.md` |
| 单个页面/功能 | 功能名（中文短语，10 字内） | `提交记录页.md` |

> 页面类文档的硬要求：必须写清**数据从哪来、状态怎么变、用户看到什么**三件事，
> 不能写成组件 API 说明或截图表。做不到这三条，说明该拆成按机制写的多篇。

- **不带日期前缀**（与 `notes/YYYY-MM-DD_主题.md` 区分：这里按类/机制命名，notes 按主题+日期命名，两者都只保留一份正文）；
- 一篇只讲一个主题；拆不开就说明颗粒度选大了；
- 文件名即主题名，重命名时必须同步修反向链接。

### 2.3 单篇结构模板

```markdown
# <类名/机制名>：<一句话定位>

> 颗粒度：… 代码截至 YYYY-MM-DD。历史见 [链接]。

## 0. 全链路一览        ← ASCII 流程图 + 环节表，先给整体
## 1. 代码层面：完整工作链路  ← 逐段走读，类#方法级引用，写清分支与副作用
## 2. 抽象思想层面：设计理念  ← 每条思想锚定到具体代码落点，不空谈
## 3. 边界与已知取舍      ← 这个设计在哪里失效/妥协
## 4. 相关文档
```

两个层面是硬要求：只有代码走读是抄书，只有思想是空谈。

### 2.4 维护规则

| 规则 | 说明 |
|---|---|
| **改行为同 PR 改本文档** | 这里讲的是"现在怎么工作"，行为变了文档必须跟着变（notes 同样就地更新，见 [`../README.md`](../README.md) §5「单一正文」） |
| **引用到类#方法，不引用行号** | 行号随重构漂移，类#方法稳定 |
| **相对链接** | 同仓库文档互链用相对路径，仓库搬家不断链 |
| **增删文档同步两张索引** | 下方索引表 + [`../README.md`](../README.md) 的目录结构 |
| **一文件一入口** | 不写"XXX 模块全家桶"，一个入口讲透即可，横向全景归 `architecture.md` |

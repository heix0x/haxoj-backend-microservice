## 一、先看全貌：涉及哪几个部分

语言切换不是孤立的，它牵涉到**一个数据源 + 三个联动**：

```
languageOptions（语言配置表，静态数据）
       │
       ├─① language（当前选中的语言，ref）
       ├─② monacoLanguage（编辑器语法高亮联动，computed）
       └─③ code（代码内容联动，watch）
```

用户改下拉框时，`language` 变了，后两者自动跟着变。

## 二、语言配置表：`languageOptions`（第 157~195 行）

```ts
interface LanguageOption {
  value: string     // 传给后端的值，必须和后端枚举一致
  label: string     // 下拉框显示的文字
  monaco: string    // Monaco 编辑器的语言 id
  template: string  // 切换到这种语言时的初始代码骨架
}

const languageOptions: LanguageOption[] = [
  { value: 'java',   label: 'Java',   monaco: 'java', template: 'public class Main { ... }' },
  { value: 'c++',     label: 'C++',    monaco: 'cpp',  template: '#include <iostream> ...' },
  { value: 'golang',  label: 'Go',     monaco: 'go',   template: 'package main ...' },
]
```

**关键设计：每种语言有三个"名字"**，各管各的事：

| 字段 | 谁用 | 为什么不能统一 |
|---|---|---|
| `value: 'java'` | 后端接口 `QuestionSubmitLanguageEnum` | 后端约定的枚举值，固定字符串 |
| `label: 'Java'` | 下拉框显示 | 给用户看的，首字母大写 |
| `monaco: 'java'` | Monaco 编辑器 | Monaco 自己的语言 id，比如 C++ 在 Monaco 里叫 `cpp` 不叫 `c++` |

**为什么不写成三份配置分别写？** 因为它们是一一绑定的关系，放一个对象里，改一种语言只改一个对象、不会漏。这叫"内聚"。

## 三、`language`：当前选中的语言（第 197 行）

```ts
const language = ref('java')  // 默认 Java
const code = ref(languageOptions[0].template)  // 默认填入 Java 骨架
```

这是状态的"源头"。下拉框用 `v-model` 绑它：

```html
<a-select v-model="language" :options="languageOptions" />
```

用户在下拉框选了 C++，`language` 自动变成 `'c++'`——这是 Arco `a-select` + `v-model` 的标准双向绑定，不用手写 `@change`。

## 四、联动一：编辑器语法高亮（第 201~203 行）

```ts
const monacoLanguage = computed(
  () => languageOptions.find((item) => item.value === language.value)?.monaco ?? 'java',
)
```

模板里：

```html
<MonacoEditor v-model="code" :language="monacoLanguage" height="520px" />
```

逻辑：`language` 变了 → `computed` 自动重算 → 从配置表里找到 `value === language` 的那项 → 取它的 `monaco` 字段 → 传给编辑器 → 编辑器切换语法高亮规则。

**为什么要 find 而不直接用 `language`？** 因为 `language` 的值是 `'c++'`（后端约定），但 Monaco 不认识 `'c++'`，它要 `'cpp'`。这个 `find` 就是做翻译的。

`?? 'java'` 是兜底——万一 `find` 没找到返回 `undefined`，编辑器拿到 `undefined` 会报错，所以兜底成 `java`。

## 五、联动二：代码内容——核心难点（第 209~216 行）

```ts
watch(language, (newValue, oldValue) => {
  const newLang = languageOptions.find((item) => item.value === newValue)
  const oldLang = languageOptions.find((item) => item.value === oldValue)
  if (!newLang) return
  if (!code.value.trim() || (oldLang && code.value === oldLang.template)) {
    code.value = newLang.template
  }
})
```

这是整个语言切换里**最巧妙**的部分。

### 5.1 要解决什么矛盾

切换语言时编辑器内容要不要换？两种用户行为要兼顾：

- **用户没写代码**（还是骨架）→ 应该换成新语言骨架，不然用户看到的是 Java 骨架却选了 C++ 语法高亮，很乱
- **用户写了自己的代码** → **不能**清空！用户写了 50 行 Java，不小心碰了下拉框，代码全没了——灾难

所以判断条件是：**"代码是空的" 或 "代码还是上一个语言的骨架" → 换骨架；否则保留用户代码**。

### 5.2 逐行拆

```ts
watch(language, (newValue, oldValue) => { ... })
```

`watch` 的第一个参数是要"盯"的数据（`language`），回调的两个参数是 `(新值, 旧值)`。用户从 Java 切到 C++，`newValue='c++'`、`oldValue='java'`。

```ts
const newLang = languageOptions.find((item) => item.value === newValue)
const oldLang = languageOptions.find((item) => item.value === oldValue)
```

用新旧值各自去配置表里查出完整的语言对象（要拿 `template`）。

```ts
if (!newLang) return
```

兜底：万一传了个不在配置表里的值，直接不做任何事。

```ts
if (!code.value.trim() || (oldLang && code.value === oldLang.template)) {
  code.value = newLang.template
}
```

核心判断，两个条件满足**任一**就换骨架：

| 条件 | 含义 | 场景 |
|---|---|---|
| `!code.value.trim()` | 代码去空白后是空 | 用户手动删光了代码 |
| `code.value === oldLang.template` | 代码和上一语言的骨架**一模一样** | 用户从没改过骨架，只是切语言试试 |

两个都不满足 → 说明用户写了自己的代码 → 不动 `code`。

### 5.3 为什么用 `watch` 而不是 `@change`（注释里专门说了）

```ts
// 不能依赖 @change 事件——a-select 的 v-model 在
// change 触发前就已更新，事件回调里读到的 language 已经是新值，拿不到旧语言
```

这是实战中非常容易踩的坑。`a-select` 的事件触发顺序是：

```
用户选了 C++
  ↓
v-model 先更新：language = 'c++'     ← 这一步立刻发生
  ↓
@change 事件回调被触发               ← 这时候 language 已经是 'c++'
```

如果用 `@change`：

```ts
// 错误写法
const handleChange = () => {
  // 想拿"旧语言"……但 language 已经是新值了！
  const oldLang = languageOptions.find(item => item.value === language.value)
  // oldLang 实际上拿到的是新语言，不是旧语言 ❌
}
```

而 `watch` 的回调签名天然提供 `(新值, 旧值)`，不需要自己去记"之前是什么"。这正是 `watch` 比 `@change` 更适合这个场景的原因。

### 5.4 为什么不用 `watchEffect`

`watchEffect` 会自动收集依赖，但它**拿不到旧值**——它的回调只有一个参数。这里需要旧值来对比骨架，所以必须用 `watch`。

## 六、三个响应式 API 的分工总结

| API | 用在哪 | 特点 |
|---|---|---|
| `ref` | `language`、`code` | 存状态，可读写 |
| `computed` | `monacoLanguage` | 派生值，自动重算，**无副作用** |
| `watch` | `code` 的联动 | 有旧值参数，能对比，**有副作用**（改了 `code`） |

这正好是 Vue 3 组合式 API 的经典分工：`ref` 管状态、`computed` 管派生、`watch` 管副作用。理解了这三个的边界，你以后写联动逻辑就不会选错工具。

## 一句话总结

> 语言切换的机制 = 一张配置表把"后端值/显示名/编辑器 id/代码骨架"绑在一起，`v-model` 绑 `language` 做选择源，`computed` 把 `language` 翻译成 Monaco id 驱动高亮，`watch(language, (new, old) => ...)` 拿到新旧值判断"代码是不是还是旧骨架"来决定要不要替换——只在用户没写自己代码时才换骨架。

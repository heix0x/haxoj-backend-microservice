## 1. 为什么需要这种调试方式

### 传统 `console.log` 的局限

在排查 Monaco 编辑器问题时，我最初用 `console.log` 输出调试信息。但遇到了两个问题：

| 问题 | 原因 |
|---|---|
| 控制台日志太多太杂 | 页面本身有大量日志，调试日志被淹没 |
| 日志含对象/数组，展开后格式混乱 | `console.log` 输出对象时是可折叠树形，不方便复制 |

### 需要的是什么

我需要一种方式：
- **只收集我关心的日志**，过滤掉无关信息
- **能完整导出**，方便贴到对话里给我分析
- **不依赖控制台渲染**，避免对象折叠/省略

## 2. `window.__log` 是什么

### 原理

在代码里创建一个数组挂在 `window` 上，把调试信息以**字符串**形式 push 进去：

```ts
// 1. 暴露编辑器实例和日志缓冲到 window
;(window as any).__editor = editorInstance
;(window as any).__log = []

// 2. 定义一个写入函数
const dbg = (s: string) => {
  ;(window as any).__log.push(s)
}

// 3. 在事件回调里调用
editorInstance.onDidChangeModelContent((e) => {
  const v = editorInstance.getValue()
  dbg('[change] full=' + JSON.stringify(v))
  emit('update:modelValue', v)
})
```

### 为什么挂到 `window` 上

`window` 是浏览器的全局对象，**在控制台里可以直接访问**。挂上去之后：

- 代码里用 `(window as any).__log` 写入
- 控制台里用 `window.__log` 读取
- 两边共享同一个数组实例

### 为什么用字符串而不是对象

```ts
// ❌ 存对象：控制台里展示为可折叠树形，不便复制
dbg({ type: 'change', value: v })

// ✅ 存字符串：一行纯文本，方便批量复制
dbg('[change] full=' + JSON.stringify(v))
```

`JSON.stringify` 把对象/数组序列化成字符串，换行符 `\n` 也会被转义成 `\\n`，这样在日志里能清楚看到内容里有没有换行。

## 3. 为什么控制台里看不到日志

### 关键原因：代码里只 `push`，没 `console.log`

看调试代码的结构：

```ts
const dbg = (s: string) => {
  ;(window as any).__log.push(s)   // ← 只写入数组
  // 没有 console.log(s)！
}
```

`push` 只是往数组里加数据，**不会在控制台打印任何东西**。数据静默地积累在 `window.__log` 数组里，只有你主动去读它才会看到。

### 对比：两种写法的区别

| 写法 | 控制台可见？ | 可导出？ | 适用场景 |
|---|---|---|---|
| 只 `console.log(s)` | ✅ 可见 | ❌ 不方便复制 | 临时看一眼 |
| 只 `window.__log.push(s)` | ❌ 不可见 | ✅ 方便批量导出 | 需要完整序列 |
| 两者都用 | ✅ 可见 | ✅ 方便导出 | 最保险（调试完删） |

在这次排查中我选了"只 push"，目的是：
- 避免控制台被刷屏（按键事件高频触发）
- 保证日志序列完整有序，方便整体分析

### 如果你想在控制台也看到

只需在 `dbg` 函数里加一行：

```ts
const dbg = (s: string) => {
  ;(window as any).__log.push(s)
  console.log(s)          // ← 加这行，控制台也能看到
}
```

## 4. `copy()` 命令是什么

### `copy` 是浏览器控制台的内置函数

`copy()` 是 Chrome/Edge/Firefox 开发者工具**控制台专属**的函数，**不是 JavaScript 语言标准**，只在控制台里可用。

作用：把参数复制到**系统剪贴板**。

```js
copy("hello")        // 剪贴板里现在是 "hello"
copy(window.__log)   // 剪贴板里现在是数组的字符串形式
```

### 这次用的完整命令

```js
copy(window.__log.join('\n'))
```

逐层拆解：

| 片段 | 作用 |
|---|---|
| `window.__log` | 取到调试日志数组，如 `['[change]...', '[watch]...', '[ev.cap]...']` |
| `.join('\n')` | 用换行符把数组拼成一个大字符串，每条日志占一行 |
| `copy(...)` | 把这个大字符串复制到剪贴板 |

之后你 `Ctrl+V` 粘贴到对话里，我就能看到完整日志了。

### 为什么不用 `console.log` 截图

| 方式 | 缺点 |
|---|---|
| 截图控制台 | 图片里文字不能复制、可能被截断、换行符看不见 |
| `copy()` + 粘贴文本 | 纯文本、完整、可搜索、换行符可见 |

## 5. 完整调试流程

### 第一步：在代码里埋日志点

```ts
;(window as any).__editor = editorInstance   // 暴露实例，方便手动操作
;(window as any).__log = []                   // 日志缓冲
;(window as any).__noEmit = false             // 可选：调试开关

const dbg = (s: string) => {
  ;(window as any).__log.push(s)
}
```

### 第二步：在关键事件回调里写日志

```ts
// 内容变化
editorInstance.onDidChangeModelContent((e) => {
  dbg('[change] full=' + JSON.stringify(editorInstance.getValue()))
  emit('update:modelValue', editorInstance.getValue())
})

// textarea 真实事件
taEl.addEventListener('beforeinput', (e) => {
  dbg('[ev] ' + (e as InputEvent).inputType + ' taValue=' + JSON.stringify((e.target as HTMLTextAreaElement).value))
}, true)

// watch 回写
watch(() => props.modelValue, (newVal) => {
  dbg('[watch] newVal=' + JSON.stringify(newVal) + ' equal=' + (cur === newVal))
})
```

### 第三步：浏览器里操作复现

1. F12 打开控制台
2. `window.__log.length = 0` 清空旧日志
3. 在编辑器里真实操作（按键、选中、复制等）
4. 操作完成后导出日志

### 第四步：导出日志给我

```js
// 控制台里执行
copy(window.__log.join('\n'))
```

然后 `Ctrl+V` 粘贴到对话里。

### 第五步：手动检查状态

```js
// 查看当前编辑器内容
window.__editor.getValue()

// 查看 DOM 结构
document.querySelectorAll('.monaco-editor textarea').forEach(t => console.log(t.className, t.readOnly))

// 手动执行命令测试
window.__editor.trigger('test', 'deleteLeft', null)
```

## 6. 其他常用控制台调试技巧

### 6.1 `browser_evaluate`（自动化浏览器执行 JS）

在 Trae 的浏览器自动化里，可以用 `browser_evaluate` 在页面里执行任意 JS 并返回结果：

```js
// 检查 DOM 结构
return {
  editor: document.querySelectorAll('.monaco-editor').length,
  textarea: document.querySelector('.monaco-editor textarea')?.readOnly,
  eol: window.__editor?.getModel().getEOL()
}
```

适合：不需要真实键盘操作、只查状态的场景。

### 6.2 `$0`（最近选中的元素）

在 Elements 面板选中一个元素后，控制台里 `$0` 就是它：

```js
$0.value          // 查看它的值
$0.className      // 查看类名
$0.getAttribute('readonly')  // 查看属性
```

### 6.3 `monitorEvents` / `unmonitorEvents`

监听某个元素的所有事件：

```js
monitorEvents(document.querySelector('.monaco-editor textarea'))
// 然后操作编辑器，控制台会打印每个事件的详细信息
unmonitorEvents(document.querySelector('.monaco-editor textarea'))  // 停止
```

### 6.4 `getEventListeners`

查看某个元素上绑了哪些事件监听器：

```js
getEventListeners(document.querySelector('.monaco-editor textarea'))
```

### 6.5 断点调试 `debugger`

在代码里加 `debugger` 语句，浏览器会自动暂停：

```ts
taEl.addEventListener('beforeinput', (e) => {
  debugger  // ← 浏览器会在这里暂停，可以查看调用栈、变量值
}, true)
```

适合：需要逐步执行、查看中间状态的复杂问题。

### 6.6 Performance 面板

录制一段操作，查看性能瓶颈和事件时序：

1. F12 → Performance 标签
2. 点录制按钮
3. 操作编辑器
4. 停止录制，查看事件时间线

## 7. 什么时候该用这种方法

### 适合用 `window.__log` 的场景

| 场景 | 原因 |
|---|---|
| 高频事件（按键、输入） | `console.log` 会刷屏 |
| 需要完整事件序列 | 要看事件先后顺序和因果关系 |
| 需要导出给我分析 | `copy()` 比 screenshot 更方便 |
| 自动化浏览器抓不到 console | `browser_evaluate` 读 `window.__log` 更可靠 |

### 不需要用的简单场景

| 场景 | 更简单的方式 |
|---|---|
| 查一个变量值 | 直接控制台输入变量名 |
| 查 DOM 结构 | Elements 面板 |
| 查一个按钮点击是否触发 | `console.log` 就够了 |
| 查网络请求 | Network 面板 |

## 附：本次排查的关键日志片段

用户导出的日志里，决定性证据是这段：

```
[ev.cap] beforeinput key/type="insertFromPaste"  ← 粘贴：有 [change] 跟随
[change] [{"range":"...","text":"window.__log.length = 0"}]  ✅ 模型更新

[ev.cap] beforeinput key/type="insertLineBreak"  ← 回车：有 [change] 跟随
[change] [{"range":"...","text":"\\n"}]  ✅ 模型更新

[ev.cap] beforeinput key/type="deleteContentBackward"  ← 退格：没有 [change]！
（后面没有 [change] 记录）  ❌ 模型未更新
```

对比清晰可见：**插入类操作触发 `[change]`，删除类操作不触发 `[change]`**——这就是 beforeinput 拦截器修复的依据。

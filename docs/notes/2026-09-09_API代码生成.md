# 前端 API 代码生成（openapi-typescript-codegen）

> 日期：2026-09-09
> 项目：haxoj
> 作用：从后端 Swagger/OpenAPI 文档一键生成前端 TS 请求代码，免手写 API 层

---

## 1. 它是干什么的

后端（Spring Boot + knife4j）会暴露一份**接口文档**（OpenAPI/Swagger JSON）。本工具根据这份文档，自动生成一整套前端 TS 代码：

- `src/api/services/*` —— 每个 Controller 对应一个 Service 类
- `src/api/models/*` —— 每个实体/DTO 对应一个 TS 类型
- `src/api/core/*` —— 请求封装（axios、错误处理、OpenAPI 配置）
- `src/api/index.ts` —— 统一出口

**好处**：后端加接口 → 重新生成 → 前端立刻有类型齐全的调用代码，手写零错误。

## 2. 前置条件

| 条件 | 说明 |
|---|---|
| 后端运行中 | 文档来自 `http://localhost:8101`，后端停了拉不到 |
| 文档地址正确 | 本项目需带分组参数：`/api/v2/api-docs?group=default` |
| 依赖已安装 | `openapi-typescript-codegen`（devDependencies） |

## 3. 怎么用

```bash
npm run api:generate
```

前提：后端 8101 在运行。执行后自动覆盖更新 `src/api/`。

## 4. 脚本配置（package.json）

```json
"api:download": "curl -s -o api-docs.json \"http://localhost:8101/api/v2/api-docs?group=default\"",
"api:generate": "npm run api:download && openapi --input api-docs.json --output src/api --client axios --useOptions && node scripts/postprocess-api.cjs"
```

### 参数含义

| 参数 | 作用 |
|---|---|
| `--input` | 接口文档来源（本地 JSON 文件） |
| `--output` | 产物输出目录，本项目为 `src/api`（与现有代码同目录，覆盖更新） |
| `--client axios` | 生成 axios 风格的请求代码 |
| `--useOptions` | 方法参数用对象解构风格（`{ xxxRequest }`），保持与现有代码一致 |
| `node scripts/postprocess-api.cjs` | 生成后的自动修补脚本（见下） |

### 为什么是「先下载、再生成、后修补」三步

1. `openapi-typescript-codegen` 直接传 http URL 时，内部 json-schema-ref-parser 拉取文档在这台 Windows 机器上会失败（报 `Unable to resolve $ref pointer`，本质是把 URL 当本地文件读了）。绕法是先用 `curl` 下载成本地 `api-docs.json`，再从本地文件生成——稳定可靠。
2. 生成器会**清空重建** `src/api` 的 `core`/`models`/`services` 目录，`OpenAPI.ts` 的 BASE 会被重置为硬编码 `http://localhost:8101/api`（会拼出双 `/api`）。后置脚本幂等地把它改回 `import.meta.env.VITE_API_BASE_URL || 'http://localhost:8101'`。

## 5. 如何避免自定义文件被生成器清空（重要）

生成器会删除 `src/api` 下它不产出的文件。**铁律：手写代码一律不放 `src/api`，自定义逻辑放 `src/plugins`、`src/utils` 等**。

已落地的处理：

| 原文件（会被清） | 现归宿 |
|---|---|
| `src/api/core/axiosInterceptors.ts`（全局 axios cookie/拦截器） | 合并进 `src/plugins/axios.ts`，main.ts 统一 `import '@/plugins/axios'` |
| `OpenAPI.ts` 的 BASE 人肉修改 | `scripts/postprocess-api.cjs` 每次生成后自动修补 |

`scripts/postprocess-api.cjs` 是幂等的：检测到已是 env 写法就跳过，可反复执行，是唯一登记"生成产物需微调"的地方。

## 6. 生成产物结构

```
src/api/
├── core/       # 纯生成：OpenAPI.ts / request.ts / ApiError.ts 等（BASE 由后置脚本修补）
├── models/     # 纯生成：数据模型类型
├── services/   # 纯生成：接口调用类
└── index.ts    # 纯生成：统一导出
```

### 用法示例

```ts
import { QuestionControllerService } from '@/api'
// 调用 GET /question/get/vo
const res = await QuestionControllerService.getQuestionVoByIdUsingGet({ id })
```

## 6. 踩过的坑

### 坑 1：`openapi` 命令找不到（CommandNotFoundException）

- **现象**：裸敲 `openapi ...` 报「无法识别」
- **原因**：npm 本地装的二进制在 `node_modules\.bin`，该目录不会自动进 PATH
- **解决**：用 `npx openapi ...`，或写进 npm script（npm run 会自动把 `.bin` 加进 PATH）

### 坑 2：文档 404，报 `Unable to resolve $ref pointer`

- **现象**：`--input http://localhost:8101/api/v2/api-docs` 解析失败
- **原因**：后端 knife4j **开了分组**，不带参数就 404（返回 HTML 错误页，不是 JSON）
- **解决**：URL 加 `?group=default`；已确认 `http://localhost:8101/api/v2/api-docs?group=default` 返回 200 JSON

### 坑 3：直接拉 http 文档仍失败

- **现象**：URL 正确（浏览器/Invoke-WebRequest 都能拿 200），工具仍报错
- **原因**：工具内部拉取 http 的链路在这台机器上不可用（栈落在 json-schema-ref-parser 的 readFile）
- **解决**：改用 `curl` 先下载成本地文件，再从本地文件生成（当前脚本方案）

### 坑 4：请求路径重复（/api/api/xxx）

- **现象**：最终请求变成 `http://localhost:8101/api/api/user/login`
- **原因**：`.env` 的 `VITE_API_BASE_URL` 与后端文档 `servers` 里都带了 `/api`
- **解决**：`.env` 里设 `VITE_API_BASE_URL=http://localhost:8101`（不带 `/api`）。详见 `API_GENERATION_GUIDE.md`

## 7. 注意事项

- `src/api/` 是**生成产物**，手动改动会在下次生成时被覆盖（core 里 BASE 等配置除外，一般保留）
- 生成后若 `core/OpenAPI.ts` 的 BASE 被重置，需确认 `.env` 中的 `VITE_API_BASE_URL` 是否正确
- 临时文件 `api-docs.json` 已加入 `.gitignore`，不会入库
- `API_GENERATION_GUIDE.md`（项目根目录）里有更早的排查记录，可对照参考

# 创建题目功能实现笔记

> 日期：2026-09-09
> 项目：haxoj 前端
> 页面：`src/views/CreateQuestion.vue`（管理员向题库新增题目的表单页）

---

## 1. 功能概述

管理员在页面中填写题目的**基本信息 + 复杂 JSON 字段**（标签、判题配置、判题用例），
前端把数据组装成 `QuestionAddRequest`，POST 到后端 `addQuestion` 接口完成入库。

核心亮点：把后端两类 JSON 复杂字段，用**结构化的动态表单**呈现——
- `tags`（字符串数组）→ 标签动态增删
- `judgeCase`（对象数组）→ 可增删的用例卡片
- `judgeConfig`（嵌套对象）→ 拆成三个结构化数字输入

## 2. 页面入口与配套改动

| 文件 | 作用 |
|---|---|
| `src/views/CreateQuestion.vue` | 页面本体 |
| `src/router/routes.ts` | 注册 `/create/question`：`access: ADMIN` + `hideInMenu: true` + `activeMenu: 'admin'` |
| `src/views/Admin.vue` | "题目管理"面板提供"创建题目"按钮跳转 |

> 约定：管理类子页面不占顶栏，从管理员中心内部进入；访问该页时顶栏仍高亮"管理员中心"。

## 3. 数据模型：与后端/生成代码对齐

页面提交对象对应自动生成的 `QuestionAddRequest` 类型（`src/api/models/QuestionAddRequest.ts`）：

| 字段 | 类型 | 页面对应控件 |
|---|---|---|
| `title` | string | `a-input` |
| `tags` | string[] | 动态标签（输入 + a-tag） |
| `content` | string | MdEditor（Markdown 题面） |
| `answer` | string | MdEditor（Markdown 答案） |
| `judgeConfig` | `{ timeLimit, memoryLimit, stackLimit }` | 三个 `a-input-number` |
| `judgeCase` | `{ input, output }[]` | 可增删的用例卡片 |

## 4. 表单状态设计

```ts
// 工厂函数：每次返回全新默认值对象（不是共享常量！）
const createDefaultForm = () => ({
  title: '',
  tags: [] as string[],
  content: '',
  answer: '',
  judgeConfig: createDefaultJudgeConfig(),   // 时间1000ms / 内存256MB / 栈128MB
  judgeCase: [{ input: '', output: '' }],    // 默认保留一条空用例
})

const form = reactive(createDefaultForm())
```

**关键点**：默认值用工厂函数而非常量对象。`reactive`/重置时如果指向同一常量对象，
重置会带上上次编辑的脏数据（内存/响应式共享问题）；每次 `createDefaultForm()` 生成全新对象才安全。

重置就是一行：

```ts
const handleReset = () => {
  Object.assign(form, createDefaultForm())  // 用新默认对象整体覆盖
}
```

## 5. 复杂字段的动态表单实现

### 5.1 标签（string[]）动态增删

模板：一个输入框 + "添加"按钮 + `v-for` 渲染可关闭的 `a-tag`。
回车（`@press-enter`）与点击按钮都走 `addTag`：

```ts
const addTag = () => {
  const value = tagInput.value.trim()      // 1. 去空格
  if (!value) return Message.warning('请输入标签内容') // 2. 空校验
  if (form.tags.includes(value)) return Message.warning('标签已存在') // 3. 去重
  form.tags.push(value)                    // 4. 入数组
  tagInput.value = ''                      // 5. 清空输入框
}
const removeTag = (index: number) => form.tags.splice(index, 1)
```

### 5.2 判题配置（嵌套对象）结构化

`judgeConfig` 在数据库里是 JSON 字符串，页面不直接编辑 JSON，而是拆成三个数字输入框直接双向绑定嵌套属性：

```html
<a-input-number v-model="form.judgeConfig.timeLimit" ... />
<a-input-number v-model="form.judgeConfig.memoryLimit" ... />
<a-input-number v-model="form.judgeConfig.stackLimit" ... />
```

最终组装时浅拷贝一份防止污染表单：

```ts
judgeConfig: { ...form.judgeConfig },
```

### 5.3 判题用例（对象数组）可增删

模板：`v-for` 渲染用例卡片，每张卡片有 input / output 两个 `a-textarea` 与"删除"按钮。

```ts
const addCase = () => {
  form.judgeCase.push({ input: '', output: '' })  // 新增一张空卡片
}
const removeCase = (index: number) => {
  form.judgeCase.splice(index, 1)                 // 删除指定下标
}
```

交互保护：
- 删除按钮 `:disabled="form.judgeCase.length <= 1"` → 至少保留一张，避免用户删空后无从下手
- 提交前过滤完全为空的用例行（用户没填的行不发给后端）

### 5.4 Markdown 富文本复用 MdEditor

题面 `content` 与答案 `answer` 直接复用封装的 MdEditor 组件：

```html
<MdEditor v-model="form.content" placeholder="..." />
```

`v-model` 即 `:model-value` + `@update:model-value` 语法糖，实现父子双向同步。

## 6. 提交链路（handleSubmit）

```
点击"提交题目"
   → 校验 title / content 必填（Message.warning 提示）
   → 过滤空的 judgeCase 行
   → 组装 QuestionAddRequest
   → loading = true（按钮转圈防重复点击）
   → 调 QuestionControllerService.addQuestionUsingPost({ questionAddRequest })
   → res.code === 0 ? Message.success + 重置表单 : Message.error(res.message)
   → 出错 catch + Message.error
   → finally 里 loading = false
```

```ts
const handleSubmit = async () => {
  if (!form.title.trim()) return Message.warning('请输入题目标题')
  if (!form.content.trim()) return Message.warning('请输入题目描述')

  const judgeCase = form.judgeCase.filter((i) => i.input?.trim() || i.output?.trim())
  const questionAddRequest: QuestionAddRequest = {
    title: form.title.trim(),
    tags: form.tags,
    content: form.content,
    answer: form.answer,
    judgeConfig: { ...form.judgeConfig },
    judgeCase,
  }

  submitting.value = true
  try {
    const res = await QuestionControllerService.addQuestionUsingPost({ questionAddRequest })
    if (res.code === 0) {
      Message.success(`创建成功，题目 id：${res.data}`)
      handleReset()
    } else {
      Message.error(res.message || '创建失败')
    }
  } catch (error) {
    console.error('创建题目失败', error)
    Message.error('创建失败，请检查网络或后端服务')
  } finally {
    submitting.value = false
  }
}
```

### 请求层说明

- `addQuestionUsingPost` 是 `api:generate` 自动生成的 Service（`src/api/services/QuestionControllerService.ts`），路径 `/api/question/add`，走全局 axios（base 由 `.env` 的 `VITE_API_BASE_URL` 提供，登录 cookie 由 `src/plugins/axios.ts` 全局拦截器携带）
- 后端统一返回 `BaseResponse{ code, data, message }`：`code === 0` 表示成功，`data` 是新题目的自增/雪花 id
- 未登录访问会被后端拒绝（页面路由层也已有管理员守卫拦截）

## 7. 可复用的开发模式小结

| 模式 | 写法 | 用在 |
|---|---|---|
| 可重置表单 | 默认值工厂函数 + `Object.assign(form, createDefaultForm())` | 整页 |
| 动态标签 | 输入框 + push/splice 数组 + 去重/空校验 | tags |
| 动态可删行 | `v-for` 卡片 + 至少保留一条的 disabled 保护 | judgeCase |
| JSON 对象编辑 | 嵌套对象 + 直接 `v-model="form.xxx.field"` | judgeConfig |
| 富文本复用 | 封装组件的 v-model | content / answer |
| 提交反馈 | loading 状态 + 成功/失败 Message + try/finally | handleSubmit |

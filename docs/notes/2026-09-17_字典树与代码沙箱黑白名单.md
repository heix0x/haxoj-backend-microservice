## 一、字典树是什么

字典树（Trie，又称前缀树）是一种专门用来**高效匹配多个关键词**的树形数据结构。

假设你要在用户代码里检测这些危险词：`Files`、`exec`、`ProcessBuilder`、`Runtime`。

普通做法是遍历每个关键词，每个都用 `code.contains(keyword)` 检查——4 个词扫 4 遍代码。

字典树的做法是把这些词**合并成一棵树**，然后只扫一遍代码就能同时匹配所有词：

```
            (root)
           /      \
          e        P
          |        |
          x        r
          |        |
          e        o
          |        |
          c        c
         / \       |
        ✗   ✓      e
       (没) (exec)  s
                    |
                    s
                    |
                    B
                    |
                    u
                    |
                    i
                    |
                    l
                    |
                    d
                    |
                    e
                    |
                    r
                    |
                    ✓ (ProcessBuilder)
```

**核心思想**：把所有关键词按字符拆开，共享相同前缀的路径。匹配时沿着树走，走到打勾的节点就说明命中了一个关键词。

## 二、为什么不用 `contains` 而用字典树

```java
// 普通做法：N 个关键词扫 N 遍
for (String word : blackList) {
    if (code.contains(word)) {
        // 命中
    }
}
// 时间复杂度：O(N × M × L)，N=词数，M=代码长度，L=词长
```

```java
// 字典树：扫一遍代码，同时匹配所有词
WordTree wordTree = new WordTree();
wordTree.add("Files");
wordTree.add("exec");
wordTree.add("ProcessBuilder");
String found = wordTree.search(code);  // 返回命中的第一个词，或 null
// 时间复杂度：O(M × L)，M=代码长度，L=最长词长
```

| | `contains` 遍历 | 字典树 |
|---|---|---|
| 扫几遍代码 | N 遍（N 个关键词） | 1 遍 |
| 关键词越多 | 越慢 | 几乎不变 |
| 适合场景 | 少量词 | 大量词（敏感词过滤、黑白名单） |

**关键词越多，字典树优势越大。** 沙箱现在只有 2 个词（`Files`、`exec`），看不出差距；但成熟 OJ 的黑名单可能有几十上百个词，字典树就是必须的了。

## 三、字典树的工作过程（用黑名单举例）

假设用户代码是：`Runtime.getRuntime().exec("rm -rf /")`

黑名单：`exec`、`Files`

### 构建树（两个词插入后）

```
(root)
├── e → x → e → c → ✓(exec)
└── F → i → l → e → s → ✓(Files)
```

### 扫描代码（逐字符走树）

```
字符位置 0: R → 树里没有 R 开头的词 → 回 root，下一位置
字符位置 1: u → 树里没有 u 开头的词 → 回 root，下一位置
...
字符位置 20: e → 树里有 e 开头的！→ 走 x → 走 e → 走 c → ✓ 命中 "exec"！
```

一次扫描就找到了 `exec`，不需要再单独找 `Files`。

## 四、项目里的实现

使用 hutool 的 `WordTree`：

```java
// 构建字典树
private static final WordTree WORD_TREE;
static {
    WORD_TREE = new WordTree();
    WORD_TREE.add("Files");
    WORD_TREE.add("exec");
    WORD_TREE.add("ProcessBuilder");
    // ... 可以无限添加
}

// 使用：在用户代码中搜索是否包含黑名单词
String matchWord = WORD_TREE.search(code);
if (matchWord != null) {
    throw new RuntimeException("包含禁止使用的关键词：" + matchWord);
}
```

### 黑白名单的区别

- **黑名单**：列出来的词**禁止使用**，出现在代码里就拒绝执行。项目目前用的这种。
- **白名单**：列出来的词**允许使用**，不在列表里的 API 一律禁止。更严格但维护成本高。

## 五、字典树的局限

字典树做关键词过滤有一个先天弱点——**它不理解语义**：

```java
// 黑名单有 "exec"，用户这样绕过：
String cmd = "ex" + "ec";           // 拼接绕过
Runtime.class.getMethod("ex"+"ec", String.class).invoke(...);  // 反射绕过
```

所以关键词过滤只是**第一层防线**，后面还需要 SecurityManager（运行时拦截）和 Docker 容器隔离来兜底。这也是为什么 OJ 安全强调"多层防御"——没有任何单层是完美的。

## 六、字典树的其他应用场景

| 场景 | 怎么用 |
|---|---|
| 搜索框自动补全 | 输入"ap"→ 树里走 a→p，返回所有以"ap"开头的词（apple、application…） |
| 敏感词过滤 | 论坛/聊天里过滤脏话，原理和黑名单完全一样 |
| 拼写检查 | 用户输错了一个字母，找树上最接近的词 |
| IP 路由表 | 路由器按 IP 前缀匹配，本质是二进制字典树 |
| 输入法联想 | 拼音 → 候选词，本质是前缀匹配 |

## 八、一句话总结

> 字典树把多个关键词按字符拆开合并成一棵树，扫描一遍文本就能同时匹配所有关键词，关键词越多优势越大。OJ 代码沙箱用它做黑名单过滤（第一层安全防线），但因为它不理解语义，必须配合 SecurityManager 和容器隔离形成多层防御。

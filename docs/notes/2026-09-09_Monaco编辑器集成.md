## 1. 背景与安装

### 为什么选 Monaco Editor

OJ 系统需要代码提交编辑器，要求：语法高亮、多语言支持、VS Code 级编辑体验。Monaco Editor 是 VS Code 的内核，功能成熟、社区活跃。

### 安装命令

```bash
npm install monaco-editor
```

> **注意**：不需要额外安装 `vite-plugin-monaco-editor`。Monaco 0.56 的 `package.json` 已内置 `exports` 映射，Vite 的 `?worker` 语法可直接导入 Worker 文件。社区插件反而可能版本不兼容。

### 参考文章

掘金：`https://juejin.cn/post/7343138429939957779`（Vue3 集成 Monaco Editor 教程）

## 2. 组件创建

### 最终文件结构

```
src/
├── components/
│   ├── MonacoEditor.vue          # 编辑器组件（核心）
│   └── custom-lang-monarch.ts    # 自定义语言 Monarch 词法定义
├── views/
│   └── Problems.vue              # 题库页面（引用组件）
└── env.d.ts                      # 类型声明（补充模块声明）
```

### MonacoEditor.vue 核心骨架

```vue
<template>
  <div ref="editorContainer" class="monaco-editor-container"></div>
</template>

<script setup lang="ts">
import { onMounted, onBeforeUnmount, ref, watch } from 'vue'
import * as monaco from 'monaco-editor'

// 编辑器容器 DOM 的引用
const editorContainer = ref<HTMLDivElement>()

// 编辑器实例：非响应式！普通变量即可（响应式代理会破坏 Monaco 内部机制）
let editorInstance: monaco.editor.IStandaloneCodeEditor | null = null

onMounted(() => {
  if (!editorContainer.value) return
  editorInstance = monaco.editor.create(editorContainer.value, {
    value: props.modelValue,
    language: props.language,
    theme: 'vs-dark',
    automaticLayout: true,   // 容器尺寸变化时自动重算布局
    editContext: false,      // 关键修复（见坑 1）
    // ...其他配置
  })
})

onBeforeUnmount(() => {
  editorInstance?.dispose()
  editorInstance = null
})
</script>
```

### 关键设计决策

| 决策 | 原因 |
|---|---|
| `editorInstance` 不用 `ref` | Vue 的响应式代理会破坏 Monaco 内部机制，普通变量即可 |
| 在 `onMounted` 里创建 | DOM 必须渲染完成且容器有宽高，`create` 才能正常工作 |
| 在 `onBeforeUnmount` 里 `dispose` | 防止内存泄漏 |
| 用 `import * as monaco from 'monaco-editor'` | 完整入口，包含所有 contrib 模块（剪贴板、命令等） |

### env.d.ts 类型声明

Monaco 0.56 的 `@bytemd/vue-next` 等包可能缺少类型声明，需补充：

```ts
declare module 'monaco-editor'
```

## 3. Web Worker 配置（Vite 集成关键）

### 为什么需要 Worker

Monaco 的 TypeScript 智能提示、JSON 校验等重活跑在 Worker 线程，防止卡死页面。不配置的话 Monaco 会去 CDN 加载 Worker，断网就挂。

### 配置代码

```ts
import editorWorker from 'monaco-editor/editor/editor.worker.js?worker'
import jsonWorker from 'monaco-editor/language/json/json.worker.js?worker'
import cssWorker from 'monaco-editor/language/css/css.worker.js?worker'
import htmlWorker from 'monaco-editor/language/html/html.worker.js?worker'
import tsWorker from 'monaco-editor/language/typescript/ts.worker.js?worker'

self.MonacoEnvironment = {
  getWorker(_, label) {
    if (label === 'json') return new jsonWorker()
    if (label === 'css' || label === 'scss' || label === 'less') return new cssWorker()
    if (label === 'html' || label === 'handlebars' || label === 'razor') return new htmlWorker()
    if (label === 'typescript' || label === 'javascript') return new tsWorker()
    // java / cpp / golang 等只需主线程 Monarch 高亮，用通用 Worker 兜底
    return new editorWorker()
  },
}
```

### 坑：Worker 导入路径

Monaco 0.56 的 `package.json` 加了 `exports` 限制（`"./*" → "./esm/vs/*.js"`），子路径会被重新映射：

```ts
// ❌ 实际解析成 esm/vs/esm/vs/... → 构建失败
'monaco-editor/esm/vs/editor/editor.worker.js?worker'

// ✅ 正确写法：exports 会自动补 esm/vs/ 前缀
'monaco-editor/editor/editor.worker.js?worker'
```

## 5. 父子组件传值（v-model 模式）

### 与 MdEditor 完全同款模式

```
父组件 ──── props（传下去）───▶ 子组件
父组件 ◀─── emit 事件（抛上来）── 子组件
```

### 子组件声明

```ts
// 接收：父组件传下来的内容和语言
const props = withDefaults(
  defineProps<{
    modelValue: string
    language?: string
  }>(),
  { language: 'javascript' },
)

// 抛出：内容变化时通知父组件
const emit = defineEmits<{
  (e: 'update:modelValue', value: string): void
}>()
```

### 数据流向

```
① 用户敲键
   ↓
② Monaco 的 onDidChangeModelContent 触发
   ↓
③ emit('update:modelValue', editorInstance.getValue())
   ↓
④ v-model 语法糖自动执行 content.value = v
   ↓
⑤ 父组件的 content 更新 → 页面展示刷新
```

### 父组件使用

```vue
<template>
  <MonacoEditor v-model="code" :language="currentLanguage" />
</template>
```

`v-model="code"` 等价于：

```vue
<MonacoEditor
  :model-value="code"
  @update:model-value="val => (code = val)"
/>
```

## 6. 坑 1：复制粘贴失效（editContext）

### 症状

- ✅ 能打字、能回车换行、能空格
- ✅ 单行内退格删字符正常
- ❌ **不能复制（Ctrl+C）/ 粘贴（Ctrl+V）**
- ❌ **不能删除空行（退格到空行后无法合并）**
- ❌ **不能剪切（Ctrl+X）**

### 排查过程

#### 第一步：误判为沙箱 iframe 问题

最初怀疑 IDE 内置浏览器预览的沙箱 iframe 限制剪贴板。但用户去 Edge 直连 localhost 仍复现，排除。

#### 第二步：误判为 Vite optimizeDeps 丢弃副作用导入

查 `node_modules/monaco-editor/esm/vs/index.js`，发现 `import './contrib/clipboard/...'` 等副作用导入都在。尝试 `optimizeDeps: { exclude: ['monaco-editor'] }`，**无效**。用浏览器自动化检查发现控制台无报错、网络请求全成功、worker 无 404，排除加载问题。

#### 第三步：浏览器自动化收集 DOM 证据（命中根因）

用 `browser_evaluate` 检查 DOM，发现：

```json
{
  "nativeEditContext": 1,   // 存在新管线元素
  "imeTextArea": 1,          // 存在只读兜底框
  "inputarea": 0,            // 传统可编辑输入框不存在
  "monacoTextarea": {
    "className": "ime-text-area",
    "readOnly": true,        // ← 只读！
    "ariaHidden": true,
    "tabIndex": -1           // ← 无法正常聚焦
  }
}
```

#### 第四步：追溯 monaco 源码定位开关

读 `nativeEditContext.js` 发现 Monaco 0.56 引入了浏览器新的 **Native EditContext API**：

- `div.native-edit-context`：真正承载 EditContext，绑定了 copy/cut/paste/keydown 监听
- `textarea.ime-text-area`：只读（readonly/tabindex=-1/aria-hidden）的 IME 兜底框，**只绑了 keydown，没有 copy/paste**

实际运行时焦点落在了**只读兜底框** `ime-text-area` 上：

| 操作 | 机制 | 结果 |
|---|---|---|
| 打字/空格/回车 | 走 EditContext 的 `textupdate` | ✅ 能用 |
| 复制/粘贴 | 监听不在焦点元素上 | ❌ 失效 |
| 空行 Backspace | 键命令路径异常 | ❌ 失效 |

追到 `editorOptions.js` 第 3184 行：

```js
editContext: register(new EditorBooleanOption(44, 'editContext', true, ...))
```

**选项名 `editContext`，默认 `true`**，仅在 Chrome/Edge 121+ 上启用。

### 修复

```ts
editorInstance = monaco.editor.create(editorContainer.value, {
  // ...
  editContext: false,  // 关闭新 EditContext 管线，回退到传统可编辑 textarea
})
```

### 验证

修复后 DOM 变化：

```json
{
  "nativeEditContext": 0,   // 新管线元素消失
  "imeTextArea": 0,         // 只读兜底框消失
  "inputarea": 1,           // 传统可编辑输入框启用
  "monacoTextarea": {
    "className": "inputarea monaco-mouse-cursor-text",
    "readOnly": false,     // ← 可编辑
    "ariaHidden": null,
    "tabIndex": 0           // ← 可正常聚焦
  }
}
```

复制粘贴恢复正常。同时撤回了无效的 `optimizeDeps.exclude` 配置。

## 7. 坑 2：删除/剪切失效（beforeinput 拦截器）

### 症状（editContext: false 修复后仍存在）

- ✅ 复制粘贴恢复正常
- ✅ 单行内退格删字符正常
- ✅ 回车换行正常
- ❌ **空行 Backspace 无法合并到上一行**
- ❌ **选中多行后 Delete 无反应**
- ❌ **Ctrl+X 剪切无反应**

### 排查过程

#### 第一步：加调试日志

在 `onDidChangeModelContent`、`watch`、textarea 的事件监听上加日志，暴露到 `window.__log` 数组，用 `browser_evaluate` 读取。

#### 第二步：浏览器自动化对照实验

用 `browser_evaluate` 模拟真实键盘事件序列（keydown → beforeinput → textarea修改 → input），分别测试 emit 开启/禁用两种模式。发现：

- **合成事件**（自动化模拟）：删除全部成功，`kdPrevented=true`
- **真实键盘**（用户操作）：删除失败

说明问题依赖真实浏览器的编辑事务，自动化复现不出来。

#### 第三步：用户提供真实日志（命中根因）

用户在 Edge 里真实操作后，用 `copy(window.__log.join('\n'))` 导出日志。关键发现：

| 操作 | inputType | `[change]` 触发？ | 结果 |
|---|---|---|---|
| 粘贴 | `insertFromPaste` | ✅ 触发 | 正常 |
| 回车 | `insertLineBreak` | ✅ 触发 | 正常 |
| **退格删除** | `deleteContentBackward` | ❌ **不触发** | **失效** |

**根因**：Monaco 0.56 的 `TextAreaEditContext`（`editContext: false` 模式）只处理**插入类** beforeinput（`insertFromPaste`、`insertLineBreak`），**不处理删除类** beforeinput（`deleteContentBackward`、`deleteContentForward`、`deleteByCut`）。浏览器直接改了 textarea 的值，Monaco 的模型却没同步更新 → 删除失效。

### 修复

在 textarea 上加 **capture 阶段 beforeinput 拦截器**：

```ts
const taEl = editorContainer.value.querySelector('textarea') as HTMLTextAreaElement | null
if (taEl) {
  taEl.addEventListener(
    'beforeinput',
    (e: Event) => {
      const ie = e as InputEvent
      const inputType = ie.inputType
      // 退格删除（含选中后 Backspace、空行 Backspace）
      if (inputType === 'deleteContentBackward') {
        e.preventDefault()
        editorInstance?.trigger('ta-fix', 'deleteLeft', null)
      }
      // Delete 键删除（含选中后 Delete）
      else if (inputType === 'deleteContentForward') {
        e.preventDefault()
        editorInstance?.trigger('ta-fix', 'deleteRight', null)
      }
      // 剪切导致的删除（Ctrl+X 删选中内容）
      else if (inputType === 'deleteByCut') {
        e.preventDefault()
        editorInstance?.trigger('ta-fix', 'deleteLeft', null)
      }
    },
    true, // capture 阶段，在 Monaco 自己的 handler 之前执行
  )

  // 剪切事件：把选中文本写入剪贴板
  taEl.addEventListener(
    'cut',
    (e: ClipboardEvent) => {
      const selection = editorInstance?.getSelection()
      const model = editorInstance?.getModel()
      if (selection && model) {
        const selectedText = model.getValueInRange(selection)
        if (selectedText) {
          if (e.clipboardData) {
            e.clipboardData.setData('text/plain', selectedText)
          } else {
            navigator.clipboard?.writeText(selectedText).catch(() => {})
          }
        }
      }
      e.preventDefault()
    },
    true,
  )
}
```

### 原理

| 步骤 | 机制 |
|---|---|
| ① 浏览器发 `beforeinput`（deleteContentBackward） | 拦截器在 capture 阶段捕获 |
| ② `e.preventDefault()` | 阻止浏览器默认行为（不直接改 textarea） |
| ③ `editorInstance.trigger('ta-fix', 'deleteLeft', null)` | 调用 Monaco 自己的删除命令 |
| ④ Monaco 更新模型 | `onDidChangeModelContent` 触发 |
| ⑤ `emit('update:modelValue', ...)` | 通知父组件 |

**不会重复处理**：单字符 Backspace 会被 Monaco keydown 拦截、不触发 beforeinput，所以只有 Monaco keydown 没拦住的删除（空行、选区、剪切）才走拦截器。

## 8. watch 回写加固

### 问题

最初的 `watch` 用 `setValue` 回写父组件传入的值：

```ts
// ❌ 原始写法
watch(() => props.modelValue, (newVal) => {
  if (editorInstance.getValue() !== newVal) {
    editorInstance.setValue(newVal)  // 整体重置模型，清空撤销栈和光标
  }
})
```

`setValue` 会整体重置模型、清空撤销栈和光标位置，可能干扰剪贴板等正在进行的操作。

### 加固

```ts
// ✅ 加固写法
watch(
  () => props.modelValue,
  (newVal) => {
    const model = editorInstance?.getModel()
    if (model && model.getValue() !== newVal) {
      // 用 applyEdits 做全量替换，保留撤销栈
      model.applyEdits([{ range: model.getFullModelRange(), text: newVal }])
    }
  },
  { flush: 'post' },  // 回调在 DOM 更新后执行，降低对编辑器键盘操作的干扰
)
```

| 改动 | 原因 |
|---|---|
| `setValue` → `applyEdits` | 保留撤销栈，不清空光标 |
| `{ flush: 'post' }` | 在 DOM 更新后执行，降低对键盘操作的干扰 |
| `model.getValue() !== newVal` | 防止"自己 emit 的值又设回自己"造成死循环 |

## 10. 排查方法论总结

### 踩过的弯路

| 弯路 | 耗时 | 原因 |
|---|---|---|
| 误判为沙箱 iframe 剪贴板限制 | 1 轮 | 没先验证独立浏览器 |
| 误判为 Vite optimizeDeps 丢副作用 | 1 轮 | 没查 DOM 就猜加载问题 |
| 静态推理多轮没收敛 | 3 轮 | 没及早用浏览器收集运行时证据 |

### 有效的定位手段

| 手段 | 命中根因的步骤 |
|---|---|
| `browser_evaluate` 读 DOM 属性 | 坑 1：发现 `readOnly=true` 的 `ime-text-area` |
| 读 monaco 源码追选项默认值 | 坑 1：追到 `editContext` 默认 `true` |
| 用户导出真实键盘事件日志 | 坑 2：发现 `deleteContentBackward` 不触发 `[change]` |
| 对照实验（emit 开启/禁用） | 坑 2：排除 v-model 回写干扰 |

### 经验教训

1. **先收集运行时证据，再推理**：静态读代码猜根因容易走弯路，浏览器 DOM 属性和事件日志是最直接的证据
2. **自动化浏览器的局限性**：合成的 `KeyboardEvent`/`InputEvent` 和真实键盘行为有差异（IME、编辑事务），不能完全替代用户测试
3. **新版库的默认行为变更**：Monaco 0.56 默认启用 EditContext API，在 Chrome/Edge 上行为和老版不同，升级时要测全量按键
4. **`beforeinput` 的 inputType 是关键诊断信号**：`insertFromPaste` / `deleteContentBackward` / `deleteByCut` 等类型能精确区分操作种类，定位"哪类操作失效"

# 前端构建工具与项目类型扫盲笔记

> 日期：2026-09-08
> 背景：搞清楚"webpack 项目"是什么、有哪些同类、我们的项目属于哪种

---

## 一、为什么需要构建工具？

浏览器没法直接运行我们写的源码：

| 源码里的东西 | 浏览器的问题 |
|---|---|
| `.vue` 单文件组件 | 浏览器不认识，要编译成 JS |
| TypeScript | 要转译成普通 JS |
| `@/components` 别名路径 | 浏览器找不到，要解析成真实路径 |
| 几百个 JS 文件、node_modules | 逐个请求太慢，要打包合并 |

**构建工具 = 翻译官 + 打包员**：开发时实时编译，上线前打包成浏览器能高效加载的产物。

平时说的"webpack 项目 / Vite 项目"，指的就是**前端工程用哪种构建工具**。

## 二、主流构建工具一览

| 工具 | 出现时间 | 特点 | 代表脚手架 |
|---|---|---|---|
| **Webpack** | 2012 | 老牌霸主，全量打包，生态最全 | Vue CLI、Create React App |
| **Rollup** | 2015 | 打包库（library）首选，产物干净 | Vue/React 自身都用它打包 |
| **Parcel** | 2017 | 零配置，开箱即用 | — |
| **esbuild** | 2020 | Go 编写，比 JS 写的快 10-100 倍 | 常作为底层引擎 |
| **Vite** | 2020 | ⭐ 当前主流，尤雨溪（Vue 作者）出品 | create-vue |
| **Rspack** | 2023 | 字节出品，兼容 webpack API 的高速替代 | Rsbuild |
| **Turbopack** | 2023 | Vercel 出品，Rust 编写 | Next.js |

脚手架演变史（以 Vue 为例）：

```
Vue2 时代：Vue CLI（webpack）    → vue create my-app
Vue3 时代：create-vue（Vite）    → npm create vue@latest
React：    CRA（webpack，已停止维护）→ Next.js 等方案
```

## 三、Webpack vs Vite 核心区别

### Webpack 的思路：先打包，再运行

```
启动开发服务器：入口 → 递归分析所有依赖 → 打包成 bundle → 启动完成
```

- 优点：功能全面、生态庞大
- 缺点：**冷启动慢**，项目越大越明显（几十秒到几分钟）

### Vite 的思路：先启动，按需编译

```
启动开发服务器：秒开
你访问哪个页面 → 才编译那个页面的模块（借助浏览器原生 ES Module）
```

- 冷启动：毫秒/秒级
- 热更新（HMR）：改一个文件只更新那一个模块
- 生产构建：底层用 Rollup，速度也不慢

> 本质原因：现代浏览器已原生支持 `import` 语法（ES Module），
> 开发时不再需要把所有文件提前捆成一个 bundle。

## 四、我们的项目是什么项目？

**Vite 项目**。

### 判断依据（看根目录文件即可）

| 看到什么 | 是什么项目 |
|---|---|
| `vite.config.ts` ✅ 我们有 | Vite 项目 |
| `webpack.config.js` | Webpack 项目 |
| `vue.config.js` | Vue CLI（webpack）项目 |
| `package.json` 里有 `react-scripts` | CRA（webpack）项目 |
| `pom.xml` / `build.gradle` | Java Maven / Gradle 项目 |

### 我们项目的证据

1. `package.json`：`"dev": "vite"`、`"build": "vite build"`、依赖 `vite: ^6.2.4`
2. 根目录存在 `vite.config.ts`：

```ts
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueDevTools from 'vite-plugin-vue-devtools'

export default defineConfig({
  plugins: [
    vue(),        // 让 Vite 能编译 .vue 单文件组件
    vueDevTools(),
  ],
  resolve: {
    alias: {
      // 这就是代码里能写 @/components/MdEditor.vue 的原因
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
})
```

## 六、一句话总结

- **构建工具解决的问题**：把开发者友好的源码（.vue/TS/别名）变成浏览器能跑的产物
- **Webpack**：先全量打包再运行，老项目主流
- **Vite**：先启动按需编译，新项目标准，快是最大卖点
- **我们的项目**：Vue3 + TS + Vite 的前端工程（Maven 构建的 Spring Boot 后端）

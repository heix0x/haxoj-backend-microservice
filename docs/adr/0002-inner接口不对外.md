# ADR-0002：inner 接口默认不对外

- **状态**：已采纳
- **日期**：2026-10-18（2026-10-21 补充过滤器合并）
- **决策人**：项目作者
- **相关**：[架构文档 §4.3](../architecture.md)、[网关接入笔记](../notes/2026-10-18_微服务网关接入.md)

## 背景

服务间通过 Feign 调用内部接口（inner）。这些接口**免鉴权**——
Feign 调用没有用户 Session，做不了登录校验。它们的安全性完全依赖「外部到不了」。

拆分初期，inner 路径挂在对外前缀下：

```
路由：Path=/api/user/**,/api/file/**
      /api/user/inner/get/id      ← 落在路由范围内，被顺手转发出去
```

结果：外部可以直接调用「改提交状态」「改通过数」这类内部写接口。

## 选项

| 选项 | 说明 | 问题 |
|---|---|---|
| A. 给 inner 加登录校验 | 复用 `@AuthCheck` | Feign 没有 Session，会把自己人拦死 |
| B. 路径收敛 + 网关拦截 + 不开路由 | 让 inner 天然不在开放范围 | 需要改路径/契约，且依赖网关 |
| C. 只靠网络隔离 | 服务只绑内网 | 单机开发时本机进程仍可直连；部署形态一变就失效 |

## 决定

**B 为主，C 为辅，A 作为后续加固（内部 token）。**

1. **路径收敛**：`/api/user/inner/**` → `/api/inner/user/**`（question、judge 同理）；
2. **网关拦截**：`GlobalAuthFilter` 对 `/api/inner/**` 和旧的 `/api/{service}/inner/**` 一律返回 **404**；
3. **不开路由**：`/api/inner/**` 不在任何 `routes` 里；judge 完全不配对外路由；
4. **网络**：业务服务只监听 `127.0.0.1`（单机开发）。

### 为什么是 404，不是 403

| 状态码 | 语义 | 后果 |
|---|---|---|
| 403 | 资源存在，但无权访问 | 等于确认「这里有一个内部端点」 |
| 404 | 路径不存在 | 与「没有这条路由」完全一致，零信息泄漏 |

## 后果

**正面**

- 外部无法通过网关触达 inner；
- inner 路径天然落不进对外路由，不依赖过滤器也不会被转发；
- 过滤器保留为「绊线」：以后有人把路由写成 `Path=/api/**`，仍然挡得住。

**负面 / 剩余风险**

- 过滤器只对**经过网关**的流量生效；直连 8101 的请求不受它保护；
- 服务绑回环只适用于单机；分机部署必须改绑内网 IP + 安全组；
- inner 本身仍无凭证，网络被打穿即裸奔。

## 后续

| 加固 | 状态 |
|---|---|
| `X-Internal-Token`（Feign 拦截器 + Controller 校验） | 未做 |
| mTLS / 服务网格 | 不适用于当前规模 |
| 数据层脱敏（`User.userPassword`） | 待做 |

## 重新评估条件

1. 服务开始跨机部署 → 必须补网络安全组，并重新验证 inner 不可达；
2. 引入第三方/外包访问内网 → 必须补内部 token；
3. 出现"内部调用被伪造"的事件 → 直接上 mTLS。
